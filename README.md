# GAME HUB V4 — لوحة التحكم + موقع العملاء + Firebase

المشروع الجديد مبني على **نفس تصميم لوحة GAME HUB V3** (خلفية بيضاء، 10 رومات + 4 طربيزات، تصميم مجسّم SVG)، مع إضافة **موقع مستقل للعملاء** وقاعدة مشتركة **Cloud Firestore** وربط Firebase Authentication.

## ملفات المشروع

| الملف | وظيفته |
|---|---|
| `index.html` | اختيار موقع العميل أو الإدارة |
| `admin.html` | لوحة الإدارة مع الجلسات والأسعار والأرباح والحجوزات وقائمة العملاء |
| `client.html` | بوابة العميل، الاسم أول مرة فقط، طلب الحجز، سجل الجلسات والفواتير |
| `cloud.js` | كل عمليات Firebase Authentication وFirestore والمعاملات والقوائم المباشرة |
| `firebase-config.js` | إعدادات مشروع Firebase الذي أرسلته (ليست سرًا) |
| `firestore.rules` | قواعد أمان Firestore؛ تمنع العملاء من تعديل الفواتير والأسعار |
| `finance.js` | عمليات حساب الدقائق والفواتير واختباراتها |
| `server.cjs` | خادم محلي بسيط، بدون npm install |

## 1) لازم تفعّل Firebase مرة واحدة

إعدادات SDK التي أرسلتها **تعرّف التطبيق فقط**، ولا تنشئ Firestore أو تفعّل Authentication تلقائيًا. لن يبدأ الحفظ السحابي بدون الخطوات الآتية.

1. افتح [Firebase Console](https://console.firebase.google.com/project/hazem-3afef/overview).
2. من **Build → Authentication → Sign-in method**: فعّل **Anonymous** (للاسم وحساب العميل المؤقت) و**Email/Password** (لحساب المدير، ولتأمين حساب العميل على أجهزة أخرى).
3. من **Build → Firestore Database**: اضغط Create database، وحدّد المنطقة المناسبة. **لا تستخدم قاعدة مفتوحة لجميع المستخدمين.**
4. من تبويب **Firestore Database → Rules**: استبدل القواعد الحالية بمحتوى `firestore.rules` كاملًا ثم **Publish**. بدون هذه الخطوة قد تظهر أخطاء permission-denied، أو تكون البيانات غير محمية.
5. من **Authentication → Settings → Authorized domains**: أضف `localhost` و`127.0.0.1` واسم النطاق الحقيقي الذي سترفع عليه المشروع عند الحاجة (المنصة قد تتطلب HTTPS في النشر).

### حساب المدير (مهم جدًا)

حتى لو شخص عرف رابط `/admin.html`، لازم يكون عنده **إيميل/باسورد مدير** و**صلاحية Firestore خاصة**.

1. من **Authentication → Users**: أنشئ مستخدمًا بإيميل وكلمة سر عبر **Add user**.
2. انسخ قيمة **UID** الخاصة بالمستخدم التي تظهر في Firebase Console.
3. من **Firestore Database → Data**: أنشئ Collection اسمها `admins`، وDocument ID **بنفس UID بالضبط**، ثم field:

   `enabled` = **boolean true** (وليس string "true").

4. افتح `admin.html` وسجّل بإيميل المدير وكلمة السر. ستُنشأ الرومات الـ14 افتراضيًا إذا كانت غير موجودة.

**ممنوع** إنشاء `admins` من كود موقع العميل. قواعد الأمان تمنع العملاء من إنشاء أو تعديل صلاحيات المدير.

## 2) تشغيل على الكمبيوتر

1. فك ضغط ملف المشروع بالكامل.
2. افتح المجلد في VS Code.
3. تأكّد أن Node.js **18 أو أحدث** موجود على الجهاز.
4. شغّل `npm start` (لا يحتاج إلى `npm install`) أو اضغط على `START_WINDOWS.bat`.
5. افتح `http://127.0.0.1:3000`، ثم اختار بوابة العملاء أو لوحة الإدارة.

> **تحذير:** لا تفتح `client.html` أو `admin.html` بالضغط المباشر `file://`؛ الوحدات البرمجية ES Modules وFirebase تحتاج خادم. لا تشغّل نسخة SQLite القديمة على نفس المنفذ في الوقت نفسه.

## 3) تشغيل من الإنترنت بحيث العملاء يدخلوا من أجهزة مختلفة

ارفع الملفات إلى **Firebase Hosting** بعد أن تفعّل Auth وFirestore وتنشر القواعد. يمكنك استخدام Firebase CLI على جهازك، بعد تثبيته وتسجيل الدخول:

```bash
npm install -g firebase-tools
firebase login
firebase use hazem-3afef
firebase deploy --only firestore:rules,hosting
```

تأكّد أنك مالك المشروع أو عندك أذونات نشر فيه قبل تنفيذ الأوامر. Firebase Hosting بيقدّم HTTPS، وتقدر تستخدم عنوان المشروع أو تربط دومين خاص. لا ترجع تستخدم الخادم المحلي `127.0.0.1` كأنه متاح لعملاء خارج جهازك.

## 4) البيانات التي تتحفظ في Firestore

- `units`: الرومات والطربيزات والأسعار والحجز وحالة الجلسة النشطة.
- `sessions`: كل الجلسات المكتملة والحالية، وقت البداية والنهاية، المدة، سعر الساعة، الفواتير، العميل المرتبط.
- `bookings`: طلبات الحجز من العملاء، الموافقة أو الرفض، الحالة، والمبلغ النهائي.
- `users`: أسماء العملاء وأرقام الهوية UID. الاسم يُكتب **مرة واحدة** فقط.
- `admins`: صلاحية المدير المحمية.
- `settings/venue`: اسم المشروع والإعدادات العامة.

الحفظ السحابي لا يحذف البيانات تلقائيًا عند إغلاق الصفحة، لكنه لا يضمن الحماية من حذف المشروع أو المسؤول أو الأعطال؛ فعّل النسخ الاحتياطي الدوري من Firebase/Google Cloud عند الاستخدام الحقيقي.

## 5) تجربة العميل

1. أول دخول إلى موقع العملاء → Firebase ينشئ حسابًا مجهولًا `Anonymous Auth` مرتبطًا بهذا المتصفح.
2. اكتب اسمك مرة واحدة → يتسجل في `users/{uid}`؛ عند العودة لنفس المتصفح لن يُطلب الاسم ثانية.
3. اطلب مدة جلسة → الطلب يدخل `bookings` ويظهر في لوحة المدير **في الوقت الحقيقي**.
4. المدير يوافق → لون الروم أصفر محجوز؛ المدير يبدأ الجلسة → أحمر مشغول؛ عند الإنهاء → أخضر متاح والفاتورة تتسجل في `sessions` وتظهر في حساب العميل.
5. عشان نفس الحساب يشتغل على أجهزة مختلفة أو بعد مسح بيانات المتصفح: افتح **حسابي → تأمين الحساب** واربطه بإيميل وكلمة سر. لو كان الحساب مجهولًا فقط ثم مسحت بيانات المتصفح، فلا يمكن ضمان استرجاع UID القديم بمجرد كتابة نفس الاسم.

> **ملحوظة:** طلب الحجز ليس حجزًا مؤكدًا؛ الموافقة من الإدارة مطلوبة. النظام الحالي يرسل طلبًا لمدة محددة للبدء في المكان، وليس نظام مواعيد مستقبلية بتاريخ وساعة؛ نقدر نطوّر تفاصيل الحجوزات في المرحلة التالية.

## 6) الربط بالنسخة القديمة

**النسخة الجديدة لا تنقل SQLite تلقائيًا إلى Firebase.** لا تمسح `arcade.sqlite` ولا تحذف نسخ V2/V3. احتفظ بنسخة احتياطية JSON وCSV من اللوحة القديمة قبل أي نقل للبيانات. الجلسات الجديدة هنا تحفظ على Firestore فقط، وليست متزامنة مع SQLite القديمة. لو عايز ترحيل سجل SQLite القديم بالكامل، لازم تنفيذ استيراد منفصل بعد مراجعة السجلات والتكرارات؛ لا ننصح بمسح القاعدة القديمة قبل التأكد من نجاح الاستيراد.

## 7) الاختبارات والملاحظات

نفّذ `npm test` لاختبار الحسابات. يوجد اختبار لتكلفة 25 دقيقة بسعر 30 جنيه للساعة (`12.50 ج.م`) واختبارات التقريب للوقت المفتوح والمدد غير الصالحة.

- SDK عبر CDN يحتاج اتصال إنترنت أثناء تشغيل الموقع؛ لو الإنترنت مغلق ستظهر مشكلة تحميل بدلاً من الاتصال بقاعدة البيانات.
- كل عمليات الحجز وبداية/نهاية جلسات المدير تستخدم Firestore transactions لمنع التداخل.
- قاعدة الأمان تمنع العملاء من تغيير الأرباح أو السعر أو إدخال جلسات أو تفعيل صلاحيات الإدارة.
- الحجز عند العميل يعتمد على الحالة لحظة الإرسال، لذلك يمكن طلب حجزين لنفس المكان قبل موافقة المدير؛ أول حجز تتم الموافقة عليه يحجز المكان، والثاني لا يمكن الموافقة عليه حتى يصبح متاحًا.
- هذا ليس نظام دفع إلكتروني؛ `amount` هو قيمة الفاتورة المحسوبة، **ولا يعني أنه تم تحصيل المال فعلًا**. لوحة التقارير تعرض قيمة الفواتير لا الربح الصافي أو المبالغ المدفوعة. لا توجد محاسبة مصروفات أو تأكيد دفع في هذه المرحلة.
